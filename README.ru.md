# FoxHole Guard

FoxHole Guard — приложение для защиты и анонимности на Android. Оно объединяет зашифрованный VPN-туннель, маршрутизацию Tor, локальный фаервол, DNS-фильтрацию и локальный мониторинг безопасности в одном приложении — без рекламы, аналитики и телеметрии.

Это больше, чем VPN-клиент: фаервол, защита DNS и Tor работают даже без профиля VPN, а весь анализ выполняется локально на устройстве.

## 🛡️ Что защищает и как

- **Приватность трафика** — VPN-туннель шифрует трафик устройства и заменяет ваш публичный IP-адрес адресом сервера. Работает на нативном Rust-ядре FoxCore со строгой проверкой TLS по умолчанию.
- **Анонимность** — маршрутизация Tor направляет TCP-трафик выбранных приложений или всего устройства через сеть Tor. Tor может работать внутри VPN-туннеля (Tor через VPN) или самостоятельно, без профиля VPN.
- **Контроль сети** — локальный фаервол блокирует доступ в интернет выбранным приложениям, ведёт журнал соединений и наполняет живую карту трафика. Работает с VPN и без него.
- **Гигиена DNS** — DNS-фильтр блокирует рекламу, трекеры, телеметрию и вредоносные домены по правилам AdGuard DNS. Защита системного DNS направляет весь системный DNS через AdGuard DNS даже без профиля VPN.
- **Безопасность устройства** — контроль новых приложений показывает источник установки и отмечает рискованные возможности (специальные возможности, доступ к уведомлениям, администратор устройства, показ поверх окон и другие). Карантин блокирует новые приложения в сети, пока вы не разрешите доступ. Анализ аномалий сообщает о необычном трафике.
- **Сохранность данных** — профили и секреты хранятся в зашифрованной локальной базе. Журналы очищаются перед отправкой; статистика и журналы не покидают устройство.

## ⚙️ Как это работает

FoxHole Guard запускает единый нативный Rust-рантайм FoxCore за Android VPN-туннелем. FoxCore владеет протокольными сессиями, маршрутизацией, перехватом DNS, учётом трафика и маршрутизацией Tor; Android-интерфейс общается с ним через узкий типизированный JNI-контракт. Режим фаервола поднимает локальную VPN-службу только для фильтрации, поэтому блокировка приложений и журнал соединений работают без удалённого сервера. Набор правил DNS встроен в приложение; совместимые подписанные обновления проверяются перед использованием.

## 🛰️ FoxHole Sentinel

FoxHole Sentinel — набор локальных проверок, которые включаются пользователем. Он не читает содержимое трафика и не является антивирусом:

- **Проверка приложений** оценивает источник установки и заявленные опасные возможности Android. Рисковый сигнал даёт пользователю контекст, но не доказывает, что приложение вредоносно. Поверх эвристик бета несёт встроенный набор индикаторов, собранный из публичных исследовательских данных [stalkerware-indicators](https://github.com/AssoEchap/stalkerware-indicators) (CC-BY-4.0, Echap): 612 идентификаторов приложений и 471 отпечаток сертификата подписи, сверка идёт офлайн. Импортируются только записи `type: stalkerware` — приложения согласованного родительского контроля в обвинение не попадают. Канал подписанных обновлений этого списка собран, но пока не размещён, поэтому до следующего релиза приложение сверяется со встроенным набором.
- **Аномалии трафика** сравнивают минутные суммарные окна с локальной нормой этого устройства. Сигналы по отдельным приложениям и фоновой активности дополнительно требуют включённой статистики и системного «Доступа к истории использования»; когда аномалии и нужные разделы статистики выключены, FoxHole не сохраняет эти окна анализа.
- **Guard-журнал** требует PIN FoxHole и включённый мониторинг событий. Он записывает установки, обновления и удаления приложений, пульс фоновых хостов и подозрительные разрывы в запечатанный локальный журнал с хеш-цепочкой. Проверка после разблокировки может обнаружить правку, пропуски или обрезание относительно последней закреплённой контрольной точки.

Стандартный **экономный** режим не держит отдельный постоянный сервис: изменения приходят через системные события Android, а WorkManager периодически сверяет пропущенное. **Усиленный** режим держит постоянную службу с видимым уведомлением, пока guard не размещён в работающей службе VPN/фаервола; это улучшает свидетельства непрерывности, но может расходовать больше энергии. Принудительная остановка Android ставит receivers и фоновые задачи на паузу до следующего запуска FoxHole. Sentinel не может предотвратить вмешательство с root-доступом или удаление данных приложения.

## 📱 Сценарии

- **Повседневная приватность** — запустите VPN и включите DNS-фильтр: трафик шифруется, реклама и трекеры блокируются.
- **Максимальная анонимность** — запустите VPN с TCP-протоколом и включите маршрутизацию Tor для нужных приложений.
- **Tor без VPN** — запустите Tor без профиля VPN; TCP-трафик выбранной области идёт через сеть Tor.
- **Защита без VPN** — включите фаервол и защиту системного DNS, чтобы блокировать приложения и фильтровать DNS вообще без профиля VPN.

## 🗂️ Smart Config

Smart Config позволяет одной подписке содержать несколько логических профилей, в каждом из которых есть несколько вариантов протокола.

Один профиль может объединять функционально эквивалентные варианты подключения через разные протоколы или транспорты. Это держит варианты синхронизированными и позволяет FoxHole Guard выбрать рабочий вариант без ручного переключения каждого URI.

Автоподключение работает полностью на устройстве. Оно пробует доступные варианты, ранжирует их по прошлым результатам и текущей сети, подключается через первый успешно прошедший проверку вариант и запоминает рабочий вариант для каждой сети. Данные о подключениях, конфигурациях, трафике и использовании приложений разработчику не отправляются.

## 🌐 DNS-фильтрация

FoxHole Guard может использовать локальный набор правил DNS для блокировки рекламных, трекерных, телеметрических и потенциально вредоносных доменов.

В beta используется встроенный DNS-фильтр на основе AdGuard DNS. Подписанный удалённый канал по
умолчанию выключен и активируется только после публикации совместимого манифеста schema 2 в
публичном репозитории Foxhole:

[foxhole-dns](https://github.com/foxhole-team/foxhole-dns)

Официальный адрес манифеста:

```text
https://foxhole-team.github.io/foxhole-dns/manifest.json
```

Набор правил DNS собирается в CI из открытого фильтра AdGuard DNS. Удалённый кандидат принимается
только после двойной проверки схемы, подписи, срока действия, монотонной последовательности,
размера и SHA-256 в Android и FoxCore.

Загружаемый файл — это скомпилированные данные DNS-фильтрации FoxCore, а не исполняемый код.

Если совместимый подписанный канал ещё не опубликован или любая проверка не проходит, FoxHole Guard
не использует загруженный файл и продолжает работать со встроенным или последним проверенным фильтром.

DNS-фильтрацию можно отключить и добавить исключения для отдельных приложений или доменов.

## 🧅 Маршрутизация через сеть Tor

FoxHole Guard может направлять TCP-трафик через сеть Tor. UDP-трафик через Tor не передаётся.

Если маршрутизация Tor включена внутри VPN, выбранный TCP-трафик идёт через сеть Tor, а UDP остаётся на обычном VPN-маршруте или блокируется настройками. Tor также может работать на маршруте устройства без профиля VPN. Если Tor остаётся на маршруте устройства при активном VPN, они работают параллельно; такой режим может увеличивать расход батареи.

## 🔒 Разрешения и приватность

FoxHole Guard использует только те разрешения, которые нужны для заявленных функций приложения.

- `INTERNET` — сетевое подключение, загрузка профилей, работа VPN/прокси, проверка подключения, работа выбранного DNS-сервера и необязательное обновление набора правил DNS.
- `ACCESS_NETWORK_STATE` и `ACCESS_WIFI_STATE` — определение состояния сети и Wi-Fi для VPN/прокси и LAN-прокси.
- `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_SPECIAL_USE` — постоянная работа VPN/прокси/фаервола и необязательного усиленного хоста Sentinel; все такие режимы показывают уведомление.
- `QUERY_ALL_PACKAGES` — показ установленных приложений для раздельного туннеля, исключений DNS, правил фаервола, локального обзора приложений и необязательной статистики по приложениям.
- `PACKAGE_USAGE_STATS` — запрашивается только при включении статистики трафика по приложениям.
- `CAMERA` — сканирование QR-кодов для импорта профилей.
- `POST_NOTIFICATIONS` — уведомления о состоянии VPN/прокси/фаервола и локальные уведомления безопасности.
- `RECEIVE_BOOT_COMPLETED` — восстановление выбранного режима запуска после перезагрузки, если это включено пользователем.
- `WAKE_LOCK` — поддержание активной сессии VPN/прокси.

Списки установленных пакетов, локальные признаки риска, статистика, диагностика, история автоподключения, пользовательские исключения DNS и состояние DNS-фильтрации остаются на устройстве, если пользователь сам их не экспортирует и не отправит.

## 📡 Сетевые запросы

FoxHole Guard может выполнять сетевые запросы для функций, выбранных пользователем:

- загрузка HTTPS-подписок;
- проверка работоспособности соединения;
- получение информации о текущем IP-адресе через настраиваемый сервис;
- работа выбранного DNS-сервера;
- необязательная загрузка обновлённого набора правил DNS из публичного репозитория Foxhole;
- обращение к сети Tor и к выбранному пользователем списку мостов, когда включён маршрут Tor;
- обращение к сети I2P через встроенный роутер i2pd, когда пользователь включает I2P;
- пользовательский экспорт или передача диагностики, если такая функция явно выбрана пользователем.

FoxHole Guard не выполняет рекламную аналитику и не отправляет телеметрию разработчику.

При обновлении DNS-фильтра приложение загружает файл манифеста и набор правил DNS. Загруженный набор используется только после проверки подписи, размера и SHA-256. FoxHole Guard не отправляет разработчику список установленных приложений, пользовательские исключения DNS, DNS-журнал и статистику фильтрации.

## ✅ Проверка релиза

Для APK, скачанного из релиза проекта:

**1. Файл — тот самый, что опубликован.** Скачайте APK и `SHA256SUMS` из одного
релиза и выполните:

```
sha256sum -c SHA256SUMS
```

**2. Подписан нами.** Хеш файла меняется с каждой сборкой и потому ничего не
говорит о том, кто её собрал. Сертификат подписи — говорит: он один и тот же во
всех релизах FoxHole Guard, и его печатает `apksigner`:

```
apksigner verify --print-certs Foxhole-<тег>-<abi>-release.apk
```

Ожидаемые отпечатки **сертификата подписи** (это не хеш самого APK):

- сертификат SHA-256:
  ```
  fcbf14862040fbe26726f06f3016ec3b027d8431c76cb4c25c13c5a06837177c
  ```

- сертификат SHA-1:
  ```
  ae609bb369398071cc5ac53c9ac10f20f43c4d01
  ```

Релизный workflow отказывается публиковать APK с другим сертификатом, а рядом с
артефактами всегда лежит `release-certs.txt`, снятый `apksigner` на сборочной
машине.

## 🛠️ Планы

> FoxHole Guard использует FoxCore как единственный сетевой рантайм и сохраняет один Android VPN-туннель при совместимых изменениях маршрутизации.

Планируемая работа:

* Сохранять бесшовную смену правил без пересоздания Android-туннеля
* Усилить split-маршрутизацию, fail-closed фаервол и восстановление соединения
* Улучшить стабильность TCP- и UDP-протоколов
* Улучшить проверку протоколов, резервную логику и обработку состояния подключения
