Foxhole - простой Android-клиент для подключения и управления профилями sing-box.

Поддерживает:

* режимы Tunnel и Proxy
* Split Tunnel для приложений и доменов
* LAN Proxy

Профили можно импортировать из файлов, буфера обмена, QR-кодов и HTTPS-подписок (включая форматы, совместимые с v2raytun).

> Без рекламы. Без аналитики. Без телеметрии.

## Ключевые функции

- Режимы: Tunnel, Proxy
- Split Tunnel (приложения + сайты)
- LAN Proxy по Wi-Fi
- Авторизация прокси
- Правила маршрутизации по сайтам
- Импорт: файл, буфер обмена, QR, HTTPS-подписки
- Multi-protocol профили с выбором протокола
- Smart start (детерминированный автовыбор протокола)
- Локальная статистика трафика
- Отображение срока подписки
- Зашифрованное хранение профилей
- Без рекламы / аналитики / телеметрии

>Примечание о разрешениях и приватности: `QUERY_ALL_PACKAGES` нужен Foxhole, чтобы показывать установленные приложения для include/exclude маршрутизации в Split Tunnel, локальной проверки установленных приложений/рисков и опциональной статистики трафика по приложениям. Usage Access (`PACKAGE_USAGE_STATS`) запрашивается только при включении статистики трафика по приложениям. Список пакетов, локальные сигналы риска, статистика трафика, диагностика и история Smart start остаются на устройстве, если вы явно не экспортируете или не отправите их сами.

## Маршрутизация Tor

Tor в Foxhole работает с TCP-трафиком. UDP-трафик не передаётся через Tor.

Если Tor включён внутри VPN, TCP-трафик выбранной области идёт через Tor, а UDP остаётся в обычном VPN-маршруте или блокируется по настройке.

Если Tor оставлен на маршруте устройства при активном VPN, VPN и Tor работают параллельно. Такой режим может расходовать больше батареи.

## Foxhole smart config

  <img src="media/have_the_courage_use_your_own_reason-fuck_you-1984.png" width="84" height="84">
</p>

Данный конфиг показывает, как одна подписка может содержать несколько профилей, каждый из которых включает несколько вариантов протоколов.

Каждый профиль (например, `profile_0`, `profile_1`) представляет собой логическую группу маршрутов:

* `profile_0` - прямое подключение
* `profile_1` - маршрутизированный трафик (например, через Tor/I2P)

Внутри каждого профиля представлены несколько вариантов протоколов:

* VLESS
* Trojan
* Hysteria2
* Shadowsocks 2022
* Outline
* WireGuard

Все варианты внутри одного профиля являются функционально эквивалентными маршрутами, реализованными через разные протоколы и транспорты.

Конфигурации WireGuard заданы в полном формате, остальные протоколы представлены в виде стандартных URI.

Дополнительные метаданные (например, `profile_1`, `profile_2`, время истечения) могут быть указаны в комментариях или параметрах и использоваться для группировки или фильтрации.

Такая структура позволяет гибко настраивать маршрутизацию и при этом держать все варианты протоколов синхронизированными внутри одного логического профиля.


### Smart start

Smart start автоматически выбирает лучший протокол для подключения.

Вместо фиксированной конфигурации приложение:

* пробует доступные варианты протоколов
* ранжирует их на основе прошлого опыта и текущей сети
* сначала пытается рекомендованный протокол
* подключается через первый успешно прошедший валидацию вариант

Алгоритм работает последовательно и ограничен:

* пробует до трёх кандидатов при автоматическом подключении
* переходит к следующему только при ошибке
* может проверить все варианты при ручном обновлении метрик

Со временем система адаптируется:

* запоминает успешные подключения (в том числе для конкретной сети)
* избегает недавно неработающих протоколов (cooldown)
* учитывает last known good
* использует отдельную память для разных сетей (network-scoped)

При ранжировании учитываются:

* история успехов и ошибок
* состояние DNS и сети
* задержка и время подключения
* признаки валидного трафика
* cooldown и недавние сбои

Из выбора автоматически исключаются:

* отключённые варианты
* просроченные профили
* протоколы в cooldown
* insecure-конфигурации без явного разрешения

Процесс быстрый и не нагружает устройство.
>Никакая телеметрия не передаётся - все решения принимаются локально на устройстве.
Приложение не отправляет данные о подключениях, трафике, конфигурациях или использовании на внешние серверы.
Выбор протокола, анализ стабильности и работа Smart start выполняются полностью на устройстве без участия сторонних сервисов.
